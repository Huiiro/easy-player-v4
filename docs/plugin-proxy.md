# 网络代理

在「设置 → 网络 → 代理设置」选择代理模式，模式切换会自动保存：

- **关闭**：不使用代理，直接连接网络。
- **使用系统代理**：跟随操作系统代理配置，无需填写地址；插件 HTTP 请求使用 Chromium 的系统代理解析，包括系统配置的 PAC 和绕过规则。
- **自定义代理**：已有有效地址时自动保存模式；首次使用需填写代理地址并点击「保存代理设置」。修改地址后也需点击保存。

例如 `http://127.0.0.1:7890` 或 `socks5://127.0.0.1:1080`。
自定义代理支持 HTTP、HTTPS、SOCKS5，暂不支持账号密码认证、手动填写 PAC 或按插件分别配置。

媒体解析工具 yt-dlp 使用系统为初始媒体 URL 解析出的首个代理；搜索使用 YouTube 地址解析。
单次解析过程中访问其他域名时继续使用该代理，不逐域执行 PAC，也不逐个尝试备用代理。

配置保存在应用数据库中，重启后保留。保存成功后，新请求使用新配置，已进行的请求继续使用原配置。
自定义代理连接失败时会返回请求错误，不自动切换到直连。原有开关配置会自动迁移为「关闭」或「自定义代理」。

代理覆盖插件 SDK 网络请求、官方插件目录刷新和安装包下载、兼容插件的宿主网络请求，
以及宿主提供的媒体解析、封面请求和 HTTP 媒体下载。不改变应用其他网络功能或原生音频引擎的流媒体连接。
插件自行创建且未使用宿主接口的网络连接不受此设置控制。

验证：`npm run test:plugin-proxy` 使用本地 HTTP 代理检查实际请求转发、取消、保存失败、SQLite 文件落盘及运行时重建后的恢复，
并检查 SOCKS5 代理规则、模式切换自动保存、重新进入页面后的回显及失败回退。
