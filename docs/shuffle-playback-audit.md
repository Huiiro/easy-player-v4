# 随机播放逻辑检查

检查范围：普通随机、智能随机、播放历史、队列增删重排、不可用歌曲、远程缓存、会话恢复，以及原生无缝切歌与 IPC 时序。

## 顺序约定

- 普通随机采用 Fisher–Yates 整轮洗牌。固定队列中每首可播放歌曲每轮恰好一次，多首可播放时避免轮末与下一轮首曲相同。
- 智能随机按推荐权重在未播放候选中抽样，每轮覆盖全部可播放歌曲。跨轮近期避重及同歌手、同专辑降权属于软约束，候选不足时优先完成本轮。
- 喜欢和减少推荐影响智能抽样概率，不构成永久跳过；智能播放首曲同样使用评分。
- 下一首按歌曲 ID 预选。反复预览、队列重排及评分刷新保留当前预选；新评分用于后续抽样。
- 上一首与向前返回按播放历史导航，不重复消耗本轮候选。用户主动选择已播歌曲允许重播。
- 不能播放的歌曲在当前队列会话中跳过；明确选中该曲时允许重试，重新建立队列后也允许重试。
- 只有一首可播放歌曲时允许循环。新增歌曲加入当前轮，删除歌曲从候选及历史中移除。

## 本次修正

1. 智能随机换轮时不再将上一轮末曲算作新一轮已播放，避免每轮少播一首。
2. 智能抽样不再修改调用方的已播集合；熟悉池与探索池分离，减少推荐歌曲不因熟悉度占据优先池。
3. 两种模式的预选保存歌曲 ID，评分刷新不重抽已预选曲目；保留洗牌顺序、预选结果和远程解析路径供恢复使用。
4. 批量加入队列对输入内部重复 ID 去重。远程缓存异常按失败候选处理，避免停止整个队列。
5. 异步缓存和打开文件后重新定位歌曲 ID，校验队列版本，避免重排、清空或停止后误记另一首歌曲。
6. 恢复时清空旧的内存历史，按过滤后的历史重新计算游标，并将较新的播放检查点纳入已播记录。跨轮检查点会提交实际已经开始的新一轮。
7. 对不同歌曲的 EOF 不再使用全局 500 毫秒节流，避免短曲结束后不再续播；旧曲事件仍按来源路径过滤。
8. 原生预加载命令携带来源曲目，在解码器锁内校验。解码器提前切换后，旧来源的目标更新及清空请求都会被拒绝。
9. 已切入但被用户删除的原生目标会切换到有效队列项，不会停留在旧曲目的界面状态。
10. 过期的异步曲目信息查询不能覆盖后续手动选曲的状态。

## 验证

- `npm run test:shuffle`：普通/智能 × 手动/无缝 × 1、2、3、8、13 首队列，共 20 组配置，每组 20 轮；检查逐轮无遗漏、无重复及轮边界。
- 同一脚本还覆盖历史返回、评分刷新、算法切换、队列增删重排、远程失败、缓存中清空、重复恢复、晚到的预加载回复、重复通知及本地/远程检查点恢复。
- `scripts/test-native-next-track.cjs` 对真正编译的原生插件打开合成静音 WAV，检查来源匹配、旧目标/清空请求拒绝及主动单曲循环；不启动音频输出。使用子进程保证测试结束后释放 Windows 文件句柄。
- 相关播放模式、持久化、推荐算法、推荐页面和统计控制回归测试，以及 TypeScript、ESLint、Prettier 检查。

原生源码已编译链接，并用独立的 `build/native-addon/shuffle-validation.node` 完成校验；默认插件复制步骤因文件权限或占用未完成。应用要使用原生来源校验，需要退出应用后重新构建原生模块并重启。上述检查不等于真实音频设备上的长时间试听。
