# 主题系统检查（2026-10-28）

## 结论

主题主链路已经统一为：偏好与运行环境 → `resolveAppearance` → 交接调度 → DOM/语义变量 → 背景与组件。主要的不统一来自组件绕过语义变量、局部配色散落在组件材料文件，以及迷你播放器单独应用主题。此次已修正这些问题，保留主题作者显式覆盖配色的能力。

视觉检查中，普通浅色采用柔和灰米色与深色文字，普通深色采用中性深底与分级亮字；歌曲背景保留封面色调，主题插件保留各自的色彩风格。主操作、危险操作、状态提示和选中项在这些材质上使用一致的语义规则。

## 已修正

| 问题                       | 证据 / 原因                                                     | 调整                                                            |
| -------------------------- | --------------------------------------------------------------- | --------------------------------------------------------------- |
| 明亮强调色上的固定白字     | 默认绿色按钮白字对比度约 2.56:1；多个业务按钮未消费按钮前景变量 | 所有主按钮统一从实际填充计算黑/白前景，业务操作使用同一语义样式 |
| 深色危险按钮仍是浅色粉底   | 危险按钮只有一套固定浅色值；删除确认在多个页面写死红底白字      | 危险表面从当前材质和危险色衍生，统一确认、删除及悬停效果        |
| 浅色状态文字过亮           | 普通浅色成功/警告文字约 2.72:1 / 2.04:1；歌曲浅色材质更明显     | 浅色语义色加深，歌曲浅色材质分别适配，保留状态色的含义          |
| 深色辅助文字过暗           | 部分插件表面上约 2.87:1                                         | 通用辅助文字提升至 OKLCH 66%，歌曲深色材质进一步加强            |
| 下拉项选中底色过重         | Select/Menu 使用 30% 强调色，部分选中项不足 4.5:1               | 两者统一为选中 8%、活动 4%，保留强调色文字、字重及选中标记      |
| 危险操作 hover 变为强调色  | 通用 `btn-hover` 无条件改变文字颜色                             | 危险文字保留自己的语义色                                        |
| 迷你播放器遗漏歌曲浅色材质 | 使用了 `--app-song-surface`，但主题载荷未传入该值               | 补齐材质同步，主窗口和迷你窗口共用调色应用函数                  |
| 迷你窗口将装饰边框用于控件 | 独立逻辑把 chrome border 写入全局组件 border                    | 保留组件边框的语义职责                                          |
| 配色代码分散               | 局部深色调色板位于 `components.css`，背景回退重复颜色常量       | 局部配色回归 `theme.css`，背景复用基础色变量                    |
| 无消费方的旧样式           | 12 组旧按钮、hover、标签等工具类已没有调用方                    | 删除约百行旧样式及歌曲背景对通用工具类的额外覆盖                |
| 变量文档滞后               | 浅色表面、文字、状态色及按钮默认值与实现不一致                  | 同步变量参考和架构说明                                          |

## 代码边界

| 层               | 位置                                                             | 职责                                           |
| ---------------- | ---------------------------------------------------------------- | ---------------------------------------------- |
| 规则解析         | `services/appearance.ts`                                         | 优先级、有效模式、背景、材质、强调色来源       |
| 应用与调度       | `services/appearanceController.ts`                               | 背景就绪前暂存配色，主/迷你窗口应用公共配色    |
| 背景资源         | `components/background/AppBackground.vue`、`BackgroundLayer.vue` | 资源就绪、预加载、冻结旧层、统一过渡、释放资源 |
| 基础与局部调色板 | `styles/theme.css`                                               | 普通明暗、歌曲材质、深色栏位和局部对比度       |
| 组件材料         | `styles/components.css`                                          | 表面、边框、阴影、透明材质与公共组件钩子       |
| 控件规范         | `styles/controls.css`                                            | 尺寸、焦点、禁用与浮层交互                     |
| 动效             | `styles/motion.css`                                              | 时长、缓动、主题整页过渡与减少动画             |
| 主题资源与契约   | `services/customTheme.ts`、`shared/theme*`                       | 声明式样式、背景候选隔离、字体、图片及校验     |

`uiStore` 仍承担偏好、预览、兼容迁移和资源协调；这些属于状态管理。歌词/音效的 V1/V2 组件仍是独立的功能迁移问题，不应再次在其中实现主题决策。后续界面新增按钮和状态提示，应消费上述公共规则。

## 验证与范围

新增矩阵共 46 个场景、1,246 个配色采样全部通过；被检查的普通文字及按钮文字对比度最低为浅色 4.68:1、深色 4.50:1。主操作和危险操作的悬停填充也纳入检查。

- `npm run test:theme-system`：使用真实 Vue 基础组件、生产 CSS 和 Chromium 颜色计算，覆盖普通明暗、10 个官方主题、歌曲极端取色及 Mica/Acrylic/Vibrancy 的配色组合；检查正文、辅助字、按钮、悬停、状态提示、真实 Teleport 下拉项和迷你播放器材质。报告输出到 `build/theme-system-audit.json`。
- 同一脚本生成 `build/theme-system-{light,dark}-{none,solid}.png` 等组件检查图。它们验证组件表面，不替代真实动态背景的绘制检查。
- `npm run test:appearance`：实际着色器、沙盒主题、主题资源、明暗切换、原生材质策略及局部对比度。
- `npm run test:background-transition`：加载等待、连续切换、整页过渡、减少动画和资源释放。
- `npm run test:theme-contract`、`npm run test:ui`：公开主题接口兼容与基础组件交互。

需要区分：原生材质检查验证前端规则和组件配色；实际 Mica 观感仍受系统壁纸与系统合成器影响。任意用户图片/视频和第三方自定义配色不能仅凭模式名保证对比度。

## 仍存在的边界

自定义媒体及旧导入主题的栏位目前按深色材料设计，缺少逐栏位亮度判断；用户将栏位设成近白，或第三方提供浅色栏位却保留深色模式时，仍可能与亮色文字冲突。任意媒体背景也没有区域亮度分析，图片本身缺少对比度时，局部文字可能需要可配置衬底。这些属于下一步的自适应对比度能力，不能由此次基础色调整覆盖全部情况。

主题预览恢复对话框保留独立固定配色，封面上的黑底白字计数、颜色选择器色板和歌词自定义颜色保留各自语义；它们不是遗留的全局明暗分支。
