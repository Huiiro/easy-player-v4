# 持续任务性能复查（2026-10-18）

检查范围为闲置、页面被 KeepAlive 缓存、窗口隐藏、播放暂停以及后台索引完成后的持续工作。本轮以代码审查和针对性生命周期/SQLite/worker 回归为主，没有对大型音乐库做长时间 CPU、内存基准，不给出新的整机降幅保证。上一轮的隐藏 SVG 动画修复保持不变。

## 已修复

| 问题                 | 原行为                                                   | 当前行为                                                                   |
| -------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------- |
| 主页时钟             | 主页被缓存或窗口隐藏后仍每秒更新                         | 仅页面激活且窗口可见时运行；恢复立即校时，保持整秒对齐                     |
| 主页和推荐页日期检查 | 定时器只在卸载时清理，缓存页继续每分钟检查并可能加载推荐 | 缓存或隐藏时停止，恢复可见时立即检查跨日                                   |
| 频谱 Canvas          | 数据为空也继续 RAF；数据稳定后仍清屏、重画               | 新数据、尺寸/配色等变化触发绘制；插值收敛后停绘；空数据不再空转            |
| 搜索索引计数         | 每秒扫描任务时，多次执行歌曲数和索引数的聚合统计         | 数据库未变化时复用计数；本连接写入、外部连接写入、重试期限到达均使缓存失效 |

新增 `useVisibleInterval` 统一处理 mounted/activated 的重复启动、deactivated、visibilitychange 和卸载清理。索引仍保留每秒发现新任务的能力，本次没有改变歌曲入库到建立索引的延迟和失败重试策略。

## 已核实但未在本轮修改

- 搜索 worker 在建立日语读音索引后，会保留 kuromoji 字典和至多 4096 条读音缓存，直到服务停止或 worker 失败。属于确定的资源保留行为，但本轮未实测其内存体积。可后续评估空闲回收与字典重载延迟的取舍。
- 星空、雨景等已启用且可见的动态背景仍需持续绘制。这是用户选择的视觉效果；本轮没有自动关闭背景或修改主题偏好。若目标是近乎零闲置占用，应使用静态背景或减少动态效果。
- 旧 `PlayerLyrics.vue` 和 `useLyricProgress.ts` 中存在持续 RAF，但当前播放器引用的是 `PlayerLyricsV2.vue`，代码搜索未发现旧组件/Hook 的运行入口，不能将其当作当前实际开销。V2 使用时钟移动状态停止逐字动画，和旧实现不同。
- 原生音频位置及分析线程在播放时启动；渲染端分析轮询受播放状态、分析消费者、页面可见性和轻量模式约束，未发现“仅启动、从未播放”就持续分析音频的入口。
