# 资料库多流派

设置 → 资料库分别配置“流派分隔符”和“歌手分隔符”，共用一个“统一分隔符”显示开关。

- 每个字符均作为一个分隔符，默认 `/；;、,，`，兼容原有扫描入库的逗号连接格式。
- 分隔后去除首尾空白、空项和重复值；分类、计数、流派列表搜索及详情匹配共用 NFC Unicode 标准化后的不区分大小写匹配键，不依赖系统语言。例如 `POP`、`Pop`、`pop` 合并为一个分类，同一首歌包含多种大小写写法也只计数一次。
- 分类名称保留最早入库歌曲中的首个写法（按歌曲 ID 升序），不改变缩写或原始标签。旧详情链接使用任意大小写均可匹配；不同流派名称、重音及完整名称边界继续区分。
- 留空则将完整文本作为单个流派，例如可保留 `Pop/Rock` 这样的名称。
- 设置立即作用于已有资料库，不要求重新扫描，不改写数据库中的原始文本或音频文件。
- “统一分隔符”开启后，歌手和流派均使用 `/` 显示，关闭则保留原始分隔符。歌手的列表、搜索、播放页、轻量模式和歌曲详情使用同一个开关；元数据编辑始终使用原始文本。
- 首次加载旧设置时，原歌手或流派开关任意一个开启，则迁移为开启；已保存的新开关优先，恢复默认值为关闭。后续只保存新的单一开关。
- 流派详情按拆分后的完整名称匹配；`Rock` 不会误匹配 `Rockabilly`，详情搜索仍使用统一歌曲搜索。
- 无流派、空白和仅包含分隔符的歌曲合并为未知流派。返回缓存中的资料库页面时重新读取分组。

## 读取和写入

扫描、重新读取标签与元数据编辑统一保留 `music-metadata` 返回的全部流派值，去重后用 `, ` 连接，继续使用现有 `song.genre` 文本字段。此前编辑读取只使用第一项，现已修复。远程 Jellyfin 的流派数组也使用相同连接规则。

| 文件类型      | 读取流派                                     | 修改/清空流派                                            |
| ------------- | -------------------------------------------- | -------------------------------------------------------- |
| MP3           | 支持多个标签值及包含分隔符的文本             | 支持，使用 NodeID3                                       |
| FLAC          | 支持多条 Vorbis GENRE 标签及包含分隔符的文本 | 支持，使用原生无重编码写回                               |
| M4A           | 支持解析器提供的全部流派值                   | 支持，使用原生无重编码写回                               |
| 裸 AAC / ADTS | 读取解析器提供的信息                         | 不支持；写入前拒绝，避免底层封装成功却丢失标签而误报成功 |
| 其他本地格式  | 取决于现有解析器                             | 当前写入器不支持                                         |
| 远程来源      | 保留服务器提供的信息                         | 不支持写回远程文件                                       |

编辑时以一个可包含多个分隔符的流派字符串写入现有标签字段，不新增跨格式的原生多值标签写入协议。清空流派后重新读取文件，并将数据库字段同步为 NULL；MP3 同时清除旧 ID3v1 的流派标记，避免回填旧值，其他字段保留。修复 MP3 写入错误被忽略的问题，以及原生写回中文文件路径失败的问题。

带内嵌封面的 M4A / FLAC 在写回时保留附加图片标记，更换封面时使用明确的输入/输出流映射。此前 B 站下载的部分带 JPEG 封面的 M4A 在再次编辑标签时，会因封面被误当作普通视频流而报 `Could not find tag for codec mjpeg` / `Unable to write metadata header`，现已修复。写回仍复制压缩音频，不重新编码；读取失败或写入收尾失败时不覆盖原文件。

以前因重新读取而截断的资料库记录，可通过歌曲菜单中的“从磁盘重新读取”恢复文件中仍存在的其他流派。

## 验证

- `npm run test:genres`：真实 SQLite 的拆分聚合、计数、未知分组、完整名称匹配、详情搜索、前端查询参数、多值读取及清空同步。
- 安装 FFmpeg 并运行 `npm run build:native` 后，上述测试额外生成中文文件名的 MP3 / FLAC / M4A，验证真实写入、读取、清空，以及修改其他字段时保留已有流派；FLAC 包含独立重复 GENRE 标签。
- `npm run test:native-metadata`：带 JPEG / PNG 封面的 M4A / FLAC 连续修改标签、更换封面、失败清理，核对封面字节及压缩音频哈希。可追加真实下载文件路径，仅操作临时副本，并核对原文件 SHA-256 未变化。
- `node scripts/test-preference-defaults.mjs`、`node scripts/test-renderer-persistence.mjs`：默认值、重置与设置持久化。
- `npm run test:song-search`、`npm run test:ui`、`npm run build`：现有搜索、组件与完整构建回归。
