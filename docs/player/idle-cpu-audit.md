# 闲置 CPU 排查（2026-10-18）

在独立 Electron 测试实例中读取当前界面偏好，保持播放器为 idle，不复制播放会话或音乐库。按进程累计 CPU 时间采样，除以实际墙钟时间和本机 28 个逻辑处理器，汇总主进程、渲染器、GPU 与 Utility；每阶段采样 10 秒。

## 定位

启动入口全量注册 `assets/svg`。其中未被任何组件引用的 `animation/play.svg`、`animation/play2.svg` 含 12 个无限 CSS 动画（random1–9 和 musicWave1–3）。SVG 精灵容器仅宽高为零，并未停止动画，未播放任何歌曲时仍持续唤醒渲染器及 GPU。

旧构建使用当前偏好采样得到总 CPU 约 0.86%–1.22%。初次对照还有动态星空背景的影响，不能把该范围全部归于 SVG 动画。最终构建下，自定义主题覆盖了星空背景，DOM 中没有背景 Canvas；因此进一步使用同一构建、同一主题进行因果对照：先采集修复后的闲置，再临时向测试实例的精灵中加入两个原始动画，最后移除它们。

同构建对照中，无这两个素材时总 CPU 约 0.01%，重新加入后约 0.38%（渲染器约 0.32%，GPU 约 0.05%）。主进程约 0.006%。这说明无效图标动画本身具有明确开销；启用并显示动态背景时，还会有正常的持续绘制开销。

## 修复与验证

将两个尚未使用的动画素材移至 `assets/animated-svg`，保留源文件，不再随启动图标精灵注入。未修改用户主题、背景设置、播放逻辑或音频线程。构建及 TypeScript 检查通过；最终运行实例不再出现上述 12 个运行中的动画。原有静态图标名称和资源均保留。

原始隔离采样位于 `build/idle-profile.json`、`build/idle-sprite-profile.json`、`build/idle-final-profile.json`、`build/idle-focused-profile.json` 和 `build/idle-causal-profile.json`。最后一个报告是同构建因果对照。短时采样受机器负载、窗口焦点、背景和处理器数量影响，不保证所有电脑都得到相同百分比。
