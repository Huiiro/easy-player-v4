# 播放性能检查与优化记录

日期：2026-10-15。环境：Windows x64，本机 WASAPI shared，48 kHz 双声道 PCM16 静音测试音频。

## 第二轮：保留窗口的约 200 MiB 目标

极致模式现使用独立的 `extreme.html` 入口和 640×360 精简窗口。切换时保存队列与偏好，销毁原界面进程；原生解码器持续运行，新窗口接管播放状态。退出后重建普通窗口并恢复原页面。联网歌词依赖及动态背景组件改为按需加载。

Windows 在新界面就绪、旧界面退出后，仅请求一次回收界面、GPU 和辅助进程的闲置工作集；承载实时音频的主进程不参与。没有周期性清理，也没有强制关闭全局硬件加速。

本机两分钟连续播放，汇总所有 Electron 进程，结果如下：

| 测量项           |        普通窗口 |        极致窗口 |
| ---------------- | --------------: | --------------: |
| 平均驻留工作集   |       492.2 MiB |       192.8 MiB |
| 驻留工作集范围   | 488.8–495.8 MiB | 178.8–200.3 MiB |
| 平均私有提交内存 |       461.8 MiB |       284.4 MiB |
| 持续播放新增欠载 |               0 |               0 |

**约 200 MiB 指驻留在物理内存中的工作集，不是提交内存硬上限。** 回收允许 Windows 重新调入活动页，内存随使用逐步回升；本次两分钟采样末值为 200.3 MiB。GPU、音频格式、歌曲队列、已加载的第三方服务及系统环境会影响结果，不能保证所有设备始终低于 200 MiB。

测试包含两个真实音频文件的播放队列，验证更换渲染进程后仍为播放状态、队列不丢失、退出后恢复界面。另一次强制跳到曲末再立即切换窗口的测试成功续播第二首，记录了 2 次边界欠载；之后的持续播放没有新增欠载。此边界结果不等同于无缝播放保证。

新原始报告：`build/playback-memory-120s.json`、`build/playback-eof-handoff.json`；窗口截图：`build/extreme-memory-check.png`。

`npm run perf:app` 默认采样极致模式 20 秒。可用环境变量延长或触发边界测试：

```powershell
$env:PERF_EXTREME_SECONDS='120'
npm run perf:app
Remove-Item Env:PERF_EXTREME_SECONDS
$env:PERF_EOF_HANDOFF='1'
npm run perf:app
Remove-Item Env:PERF_EOF_HANDOFF
```

## 已实现

- 设置 → 播放 → 极致播放模式。设置持久化；保留播放、暂停、上一首、下一首、跳转、音量及播放快捷键。
- 极致模式卸载普通界面、路由缓存、动态背景、歌词与音频控制面板，关闭桌面歌词及迷你窗口；退出后恢复普通界面与用户配置。
- 大型播放组件和背景按需加载；普通模式的页面缓存上限为 3。
- 无可见分析消费者时停止采样复制与分析。极致模式强制禁止分析请求；进度 IPC 从每秒 10 次降至约 1 次，跳转和切歌仍能及时更新。
- 分析环形缓冲从 2 秒降为 250 毫秒，容量减少 87.5%。播放所需的解码和输出缓冲保持原容量。
- 频谱使用 Goertzel 递推，混声与 Hann 窗每块计算一次，系数缓存；保持原有 64 个频段和输出幅度定义。
- 极致模式旁路可选 DSP 音效，保留输出音量、必要的格式转换及削波保护。退出时继续使用原音效配置。
- 极致模式停止下一首预解码和远程预缓存，保留到曲末正常切歌；暂停智能推荐计算与播放统计。
- 本地扫描与远程同步在任务边界等待退出模式；终止下载子进程和相关媒体请求，取消更新下载，禁止新下载、更新及歌词搜索；过滤非错误日志并停止性能条目清理定时器。

正在执行的单次扫描、元数据解析或第三方歌词网络请求可能先完成当前操作。扫描和同步退出后继续；被中断的下载需要重试。极致模式不记录期间的听歌统计，不提供无缝预加载及交叉淡化。

## 实测与限制

原生基准每个场景使用新进程，两轮，每轮预热约 1.5 秒、采样约 6 秒；验证进度推进、暂停、跳转、恢复和音频欠载计数。

| 原生场景                           | CPU 单核占用范围 | 平均驻留内存 |
| ---------------------------------- | ---------------- | ------------ |
| 频谱算法替换前，同时开启频谱与响度 | 35.91%–44.47%    | 约 66.6 MiB  |
| 频谱算法替换后，同时开启频谱与响度 | 3.61%–12.96%     | 约 66.6 MiB  |
| 最终普通播放，无分析消费者         | 1.02%–1.03%      | 约 66.6 MiB  |
| 最终极致播放                       | 0.77%–1.28%      | 约 66.5 MiB  |

这些是短时原生进程测量，存在调度与预热波动，不能据此推算所有机器上的整机百分比。频谱前后对照针对相同分析负载，并非整款应用改动前后的对照。六个最终原生场景均未记录音频欠载。

第一轮曾以独立空音乐库和独立用户数据目录启动完整 Electron 应用，检查普通 → 极致 → 恢复，采集主进程、渲染器和 GPU 等进程的 CPU 与工作集之和，无强制垃圾回收。切换与播放验证通过，未出现渲染错误；短测未观察到总内存显著下降。该版本只卸载组件，未释放整个渲染进程；上方第二轮改造已解决此问题。大型音乐库、数小时播放或其他音频后端仍需另外验证。

原始报告保存在 `build/playback-performance-before-spectrum.json`、`build/playback-performance.json`、`build/playback-app-performance.json`。构建目录不纳入 Git。

### 2026-10-16：修正窗口交接空档

独立窗口事件追踪复现进入极致模式时旧窗口先关闭、新窗口约 45 毫秒后才显示；普通页面也会在窗口切换前先挂载极致页面。现在仅在替换窗口 `ready-to-show` 并执行 `show()` 后立即销毁旧窗口，不再使用 `did-finish-load` 触发销毁，也不引入额外动画帧或播放器恢复等待。旧页面保持原布局，沉浸播放页不提前收起；极致窗口的底色与页面统一为 `#151515`。

新增独立回归脚本 `scripts/check-playback-view.cjs`，通过普通和最大化状态下的四次交接，验证新窗口显示时旧窗口仍可见、旧窗口销毁时新窗口已可见、旧页面不提前改变布局，以及尺寸位置保持。此次隔离空库测得显示耗时 126–144 毫秒，仅代表当前测试环境。报告写入 `build/playback-view-check.json`。测试不播放音频，不替代完整播放性能回归。
