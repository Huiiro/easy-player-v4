# 播放页切歌画面卡顿

播放页切歌时出现短暂画面停顿、声音正常。排查时当前队列为 2419 首，会话快照约 1.3 MB。`tryPlayQueueItem` 切换游标和 `openFile` 完成后都会同步保存完整队列，随机播放成功和原生自动接歌也存在同步保存。`savePlaybackSession` 虽然声明为 async，内部实际仍调用同步 IPC；因此切歌时渲染线程需要等待整队列序列化、跨进程传输和 SQLite 写入。

修复后：

- 切歌中的保存请求使用现有的 750 ms 合并调度，经过 `database.command('setSetting')` 异步保存，不等待数据库写入才继续播放。
- 队列歌曲的持久化快照使用 computed 缓存，游标变化不重新遍历整条响应式队列；歌曲字段、增删、重排仍会自动使缓存失效。
- 显式同步刷新保留在退出、窗口切换、队列替换等需要立即保存的位置，并取消尚未执行的延迟保存。
- 主进程的播放位置检查点保持原有更新和退出刷新规则。

## 测量与验证

`npm run test:track-switch` 使用隔离的数据目录，不读取或修改用户资料库，也不播放音频。

1. `check-track-switch.cjs` 使用真实 Vue 播放 store、Electron IPC 和 SQLite，构造 2419 首歌曲的队列。修复前一次切歌状态处理约 25–30 ms，三次切歌及合并调度共产生 7 次同步完整快照写入；修复后约 0.3–0.5 ms，三次切歌合并为 1 次异步写入。该测量不包含解码、图片、歌词或 GPU 绘制，耗时随机器变化。检查最新游标、完整队列、显式退出刷新取消延迟写入，以及队列元数据变化后缓存失效。
2. `check-player-panel-switch.cjs` 单独加载真实播放页、封面分析、专辑背景和 100 行歌词，以隔离的响应式播放数据连续切换。初始测量页面提交约 3–4 ms，封面采样约 0–12 ms，未记录到 50 ms 以上长任务。该夹具关闭节奏特效、频谱和未打开的工具弹窗，不代表所有图片、歌词长度或显卡场景的上限。

结果输出到 `build/track-switch-after.json`、`build/panel-switch-after.json`。隐藏窗口使用 16 ms 定时器模拟帧回调，记录的是回调调度间隔，不是屏幕呈现帧率。

另外运行随机播放、自动接歌、播放检查点和轻量窗口切换回归，验证保存调度变化不影响播放顺序与恢复行为。
