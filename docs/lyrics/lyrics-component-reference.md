# 歌词组件与格式支持说明

本文档描述 Easy Player 当前歌词实现，包括歌词来源、格式识别、解析规则、标准数据模型、播放器与桌面歌词的渲染能力，以及现阶段限制。本文以当前代码为准，不是未来开发计划。

## 1. 处理流程

```text
内嵌 / 数据库 / 本地文件 / 网络
                    ↓
               LyricPayload
                    ↓
       格式识别与 parseLyrics()
                    ↓
               LyricDocument
                    ↓
     PlayerLyricsV2 / 桌面歌词窗口
```

所有来源最终都会转换为统一的 `LyricLine[]`。渲染组件不需要了解歌词来自哪个平台或文件。

## 2. 支持的歌词来源

| 来源         | 标识       | 说明                                                                                 |
| ------------ | ---------- | ------------------------------------------------------------------------------------ |
| 音频内嵌歌词 | `embedded` | 通过 `music-metadata` 读取。同步文本转换为 LRC，无时间文本转换为 Plain。             |
| 数据库歌词   | `database` | 保存主歌词、翻译、音译及各自的格式字段。歌词管理器编辑或网络搜索结果均可写入数据库。 |
| 本地歌词文件 | `local`    | 从音频同目录查找歌词文件。                                                           |
| 网络歌词     | `network`  | 支持网易云和酷狗搜索；自动模式可使用首个匹配结果并缓存到数据库。                     |

默认自动加载顺序为：

```text
embedded → database → local → network
```

顺序可在设置中调整，也可以强制选择某个来源。网络自动搜索只在自动模式下作为回退使用；手动网络搜索需要在歌词管理器中选择并保存结果。

### 2.1 本地文件发现规则

本地文件按以下格式优先级查找：

```text
elrc → yrc → ttml → lrc
```

文件名依次尝试：

```text
<音频文件名（不含扩展名）>.<格式>
lyrics.<格式>
```

例如音频为 `Song.flac`，会优先查找 `Song.elrc`，随后是 `Song.yrc`、`Song.ttml`、`Song.lrc`，最后再检查 `lyrics.*`。

## 3. 支持的格式

```ts
type LyricFormat = 'lrc' | 'elrc' | 'yrc' | 'ttml' | 'plain'
```

| 格式  | 行级时间 | 词/字级时间 | 翻译轨       | 音译轨       | 备注                                                             |
| ----- | -------- | ----------- | ------------ | ------------ | ---------------------------------------------------------------- |
| LRC   | 支持     | 不支持      | 支持独立轨道 | 支持独立轨道 | 支持元数据、多时间标签和偏移量。                                 |
| ELRC  | 支持     | 支持        | 支持独立轨道 | 支持独立轨道 | 在 LRC 行内使用增强时间标签。                                    |
| YRC   | 支持     | 支持        | 支持独立轨道 | 支持独立轨道 | 支持网易云逐词时间元组。                                         |
| TTML  | 支持     | 支持 `span` | 支持独立轨道 | 支持独立轨道 | 当前实现解析基础 `p/span` 时间，不解析完整 TTML 样式与角色系统。 |
| Plain | 不支持   | 不支持      | 不合并       | 不合并       | 每个非空文本行作为无时间歌词展示。                               |

翻译和音译不是从主歌词文本中猜测出来的，而是通过 `LyricPayload.translation` 和 `LyricPayload.romanization` 作为独立轨道传入。数据库中的三条轨道可以分别声明格式。

## 4. 自动格式识别

未显式提供格式时，按以下顺序识别：

1. 包含 `<tt>` 根节点：`ttml`。
2. 包含 YRC 行和词时间元组：`yrc`。
3. 包含 `<mm:ss.xxx>` 一类增强时间标签：`elrc`。
4. 包含 `[mm:ss.xxx]` 一类行时间标签：`lrc`。
5. 其他内容：`plain`。

文件开头的 UTF-8 BOM 会被忽略。

## 5. 各格式解析规则

### 5.1 LRC

基本示例：

```lrc
[ti:歌曲名]
[ar:歌手]
[al:专辑]
[offset:120]
[00:12.340]第一句歌词
[00:15.20][00:42.20]重复出现的歌词
```

当前支持：

- `[mm:ss]`、`[mm:ss.xx]`、`[mm:ss.xxx]`。
- 秒的小数分隔符也可写为冒号。
- 同一行多个时间标签。
- `[ti:]`、`[ar:]`、`[al:]` 和 `[offset:]` 元数据。
- `offset` 使用毫秒，并应用于主歌词时间轴。
- 只有时间戳、没有文本的行会保留为解析阶段的时间标记，但不会直接作为歌词显示。
- 如果整个输入没有有效时间歌词，但存在普通文本行，则降级为 Plain。
- 只有时间标记、完全没有文本的输入被视为无歌词，以便继续尝试下一个来源。

### 5.2 ELRC

示例：

```lrc
[00:10.000]<00:10.000>Hello <00:10.500>world
[00:13.000][v1:<00:13.000>男声歌词]
[00:16.000][v2:<00:16.000>女声歌词]
[00:19.000][group:<00:19.000>合唱歌词]
[00:22.000][bg:<00:22.000>背景人声]
```

规则：

- 外层 `[mm:ss.xxx]` 是行时间。
- 行内 `<mm:ss.xxx>` 是词片段开始时间。
- 每个片段可包含空格、标点和 emoji。
- 未显式给出的片段结束时间由下一片段或整行结束时间推导。
- 末尾空文本时间标签可以作为前一片段的明确结束时间。
- 词片段会进一步按 Unicode 字符均分持续时间，供逐字动画使用。
- `[v1:...]` 和 `[v2:...]` 分别映射到左右演唱角色。
- `[group:...]` 映射为居中的合唱行。
- `[bg:...]` 映射为尺寸较小、弱化显示的背景人声行。
- 同时兼容 `[v1:]...`、`[v2:]...`、`[group:]...` 和 `[bg:]...` 前缀写法。

ELRC 仍使用 LRC 行解析器，因此有效逐词行需要带行级方括号时间标签。

### 5.3 YRC

示例：

```text
[10000,2400](10000,600,0)为理(10600,600,0)云鬓(11200,600,0)为簪(11800,600,0)银钩
```

规则：

- `[开始毫秒,持续毫秒]` 定义整行。
- `(开始毫秒,持续毫秒,保留字段)` 定义词片段。
- 如果词开始时间小于行开始时间，则按相对行时间处理；否则按绝对毫秒处理。
- 词片段同样会被拆分为字符，并在该词持续时间内均匀分配字符时间。
- 网易云网络歌词优先使用 YRC；没有 YRC 时回退到 LRC。

### 5.4 TTML

支持的基础结构示例：

```xml
<tt>
  <body>
    <div>
      <p begin="00:10.000" end="00:13.000">
        <span begin="00:10.000" end="00:11.000">Hello</span>
        <span begin="00:11.000" dur="2s">world</span>
      </p>
    </div>
  </body>
</tt>
```

当前支持：

- `p` 的 `begin`、`end`、`dur`。
- `span` 的 `begin`、`end`、`dur`。
- `123ms`、`1.5s`。
- `mm:ss.xxx` 和 `hh:mm:ss.xxx`。
- `h`、`m`、帧 `f`、tick `t` 以及 `hh:mm:ss:frames.subframes`。
- `ttp:frameRate`、`frameRateMultiplier`、`subFrameRate` 和 `tickRate`。
- `body/div/p/span` 的父子相对时间与 `timeContainer="par|seq"`。
- 对常见音乐 TTML 的绝对 span 时间写法进行兼容检测，避免在父级时间上重复累加。
- `span` 文本转换为逐词时间。
- `<br/>` 转换为歌词内换行。
- 读取 `head/metadata` 中的 `ttm:agent` 定义。
- 在 `p` 及祖先节点上继承 `ttm:agent`、`ttm:role` 和 `xml:lang`。
- 保留最近 `div` 的 `xml:id` 作为轨道标识。
- 单演唱者按首次出现顺序分配左右位置；多 agent 或 `group` agent 作为居中合唱行。
- 时间重叠的多个歌词行可同时激活并执行逐字动画。
- `ttm:role="x-bg"`、`x-background` 或 `x-background-vocal` 映射为背景人声；嵌套背景 span 会从主行拆出。
- `x-translation`/`x-translated` 和 `x-romanization`/`x-romanized` 轨道会自动合并到对应主行。

当前不支持或不保证：

- TTML 样式、布局、动画和外部资源。
- 仅根据 `xml:lang` 自动推断翻译、音译轨；没有明确角色时语言代码不足以可靠判断轨道用途。
- wallclock、SMPTE discontinuous marker 等特殊时间基准。
- repeat、动画时间以及 TTML/SMIL 的全部隐式持续时间边界情况。

### 5.5 Plain

示例：

```text
第一行歌词
第二行歌词
```

规则：

- 去除 BOM。
- 按换行拆分。
- 忽略空行并修剪首尾空白。
- 所有行的 `timeMs` 为 `0`，同时标记为 `untimed`。
- 无时间歌词不自动滚动、不支持点击精确跳转，也不生成间奏省略号。

## 6. 翻译与音译轨道

翻译和音译分别解析，再与主歌词合并：

- 使用行开始时间匹配。
- 允许最多 `30ms` 的时间差。
- 翻译写入 `line.translation`。
- 音译写入 `line.romanization`。
- 如果音译轨和主歌词都含有可对应的逐词时间，会生成 Ruby 片段，在原文上方显示音译。
- 无法建立逐词对应关系时，音译作为独立副行显示。
- 翻译和音译可以在界面设置中分别开关。

主轨偏移量会同时作用于附加轨；附加轨自身的 `offset` 会在主轨偏移基础上继续叠加。

## 7. 标准数据模型

核心结构如下：

```ts
interface LyricLine {
  timeMs: number
  endMs?: number
  text: string
  untimed?: boolean
  translation?: string
  romanization?: string
  words?: Array<{ text: string; startMs: number; endMs: number }>
  chars?: Array<{ char: string; start: number; duration: number }>
  agentIds?: string[]
  agents?: Array<{
    id: string
    name?: string
    type?: 'person' | 'character' | 'group' | 'organization' | 'other'
  }>
  roles?: string[]
  language?: string
  trackId?: string
  trackKind?: 'main' | 'background' | 'translation' | 'romanization' | 'other'
  vocalPosition?: 'left' | 'right' | 'center'
  isChorus?: boolean
  isBackground?: boolean
}
```

时间整理阶段会：

- 按行开始时间排序。
- 使用下一行开始时间推导缺失的行结束时间。
- 最后一行至少推导 `300ms` 的结束区间。
- 使用下一词开始时间或行结束时间推导缺失的词结束时间。
- 保证行和词持续时间至少为 `1ms`。

## 8. PlayerLyricsV2 渲染行为

当前播放器使用 `PlayerLyricsV2.vue`，主要能力包括：

- 根据播放位置定位当前行；显式时间重叠时可同时激活多行。
- TTML 单演唱者按稳定的左右位置显示，多演唱者或 group agent 的合唱行居中显示。
- 使用插值歌词时钟，在低频播放器位置事件之间保持逐帧连续推进。
- 播放时通过 `requestAnimationFrame` 更新逐字进度，暂停时停止外推。
- 精确逐字歌词按源时间扫字；普通 LRC 的“跟随”效果按整行时长均匀分配字符进度。
- 扫字边缘使用按字符宽度计算的柔化过渡；完成后恢复为纯高亮色。
- 逐字歌词使用沿整行移动的 Dock 式波峰，同时影响多个相邻字符，而不是单字独立跳动。
- 字符波峰前缘较窄、后缘较宽，形成快速浮起、缓慢回落的连续效果。
- 行切换使用弹簧滚动，并带有错峰的行位移、透明度和模糊变化。
- 当前行和远处行不再使用行级缩放。
- 支持左、中、右对齐。
- 支持点击有时间歌词跳转播放位置。
- 支持鼠标、触摸和键盘手动滚动；操作结束后自动回到当前行。
- 支持减少动态效果模式。
- 切歌后的首次歌词定位直接吸附，不继承上一首歌靠近底部的滚动位置。

### 8.1 歌词样式

播放器支持以下主样式：

| 样式     | 行为                                                            |
| -------- | --------------------------------------------------------------- |
| `none`   | 不使用跟随扫字效果。                                            |
| `glow`   | 使用高亮色与文字发光。                                          |
| `follow` | 普通 LRC 按整行持续时间执行逐字跟随；精确格式使用自身逐字时间。 |

颜色通过 CSS 变量提供：

```text
--lrc-default    普通歌词颜色
--lrc-highlight  当前/已扫过歌词颜色
--lrc-translate  翻译颜色
```

## 9. 自动间奏省略号

省略号采用类似 Apple Music 的自动插入逻辑：

- 歌词源中的空白时间戳只作为时间标记，不直接显示。
- 第一条有效歌词距离歌曲开始严格大于 `3s` 时生成间奏。
- 当前歌词结束到下一条有效歌词开始严格大于 `3s` 时生成间奏。
- 间隔刚好为 `3s` 时不生成。
- 未来的间奏不会预先出现在歌词阅览中。
- 播放进入间奏时间段后才显示省略号。
- 间奏结束时从布局移除，并进行滚动位置补偿，再复用正常歌词切换的弹簧动画。
- Plain 无时间歌词不生成间奏。

## 10. 桌面歌词

桌面歌词复用同一个 `resolveLyrics()` 结果，支持：

- 当前歌词与下一句歌词。
- 对唱或背景人声与主行重叠时，第二行优先显示当前重叠人声；重叠结束后恢复下一句。
- 当前行翻译。
- 行级扫光范围；优先使用首词开始和末词结束时间。
- 播放、暂停、上一首、下一首控制。
- 字体、字号、颜色、粗体、发光、扫光和背景自动隐藏设置。

空白下一行保持为空，不再使用歌手名称填充。桌面歌词目前使用整行扫光，不渲染播放器中的逐字符 Dock 波浪。

## 11. 输入限制与容错

为避免异常歌词阻塞渲染，解析器设有以下限制：

| 限制                 |           当前值 |
| -------------------- | ---------------: |
| 单轨歌词最大文本长度 | `1,000,000` 字符 |
| 最大歌词行数         |          `5,000` |
| 最大逐词条目数       |         `50,000` |

其他容错行为：

- 无效或负数时间会被忽略。
- 损坏的 TTML 或 XML 解析错误返回空歌词。
- 空来源会继续尝试下一个歌词来源。
- 重复或无结束时间的数据会在标准化阶段补齐最小持续时间。
- 网络提供者单独失败不会阻止另一个提供者返回结果。

## 12. 当前限制

- 本地自动发现仅检查 `elrc/yrc/ttml/lrc` 扩展名，不查找 `.txt` Plain 文件。
- ELRC 必须具有可解析的 LRC 行级时间标签。
- YRC 和 ELRC 的词时间会均分给词内字符，不是原生逐字符时间。
- 翻译与音译仅按时间匹配，不进行文本相似度或语义对齐。
- TTML 已保留基础 agent、角色、语言和轨道语义，并支持重叠演唱行；仍不是完整 TTML/TTML2 实现。
- 内嵌歌词只转换同步文本或普通文本，不保留提供方私有的高级逐字结构。
- 桌面歌词不展示 Ruby 音译和播放器的逐字符波浪动画。
