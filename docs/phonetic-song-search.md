# 歌曲拼音与日语读音搜索

日期：2026-10-16。状态：首版已实现，定向测试和生产构建已通过。

## 目标与范围

歌曲列表中的歌曲名、歌手、专辑、文件名支持原文包含、无声调拼音、拼音首字母、连续拼音片段、日语罗马音、平假名、片假名、简繁体和多关键词组合查询。全部歌曲、本地/远程、喜欢、歌单、历史及文件夹/专辑/歌手/流派详情使用同一搜索条件。浏览时保持原排序；搜索时默认相关度，允许手动切换其他排序。

参考 Echo 的搜索架构，独立实现适合本项目的模块。含假名的字段只生成日语读音，纯汉字字段同时尝试中文和日语读音；转换结果是候选读音，不保证特殊人名、多音字和艺术化读法全部正确。

## 模块与数据流

`src/main/search/` 包含词条生成、日语转换、查询构造、索引更新服务和 Worker。依赖 pinyin-pro、kuroshiro、kuroshiro-analyzer-kuromoji、opencc-js。

歌曲变更 → 数据库触发器记录待处理任务并使旧读音失效 → Worker 生成词条 → 主进程核对任务修订号后写入 → FTS5 触发器同步索引 → 通知列表刷新。

- `song_search`：每首歌曲各字段的派生词条、生成器版本。
- `song_fts`：FTS5 unicode61 索引。
- `song_original_fts`：v7 新增的规范化原文与 FTS5 trigram 子串索引，写入时更新。
- `song_search_pending`：持久化队列与修订号，覆盖扫描、远程同步、标签编辑、备份恢复和文件迁移。
- 更新条件仅涉及 title、artist、album、file_name；删除时级联清理。
- Worker 仅转换文本，数据库连接由主进程持有。返回时核对修订号，过期结果丢弃。

## 词条与查询规则

NFKC、小写、分隔符规范化；中文生成 1～3 字片段、全拼、完整首字母、最多 6 字的连续拼音窗口，同时保留完整形式。日语生成 Hepburn 罗马音、平片假名、最多 8 个分词的连续窗口和完整首字母；补充长音简化、助词和撇号变体。限制输入长度和转换缓存大小。

索引生成器 v2 将完整读音、读音片段、首字母和假名放在不同命名空间中。首字母仅支持至少两个字符的完整缩写匹配，不再生成任意首字母窗口或使用前缀通配；单个拉丁字符只查原文。汉字查询只查原始元数据及简繁变体，避免命中其他歌曲自动生成的错误汉字读音；假名可查额外的日语读音。

搜索分数按关键词取各字段的最佳匹配，再对关键词求和；复制的文件名与重复字段不会叠加加分。原文完整/前缀/包含、整段读音/片段/前缀、完整首字母分级计分；通常歌名优先，其后歌手、专辑、文件名，弱缩写命中低于强原文匹配。整首名称与带 Live 等额外后缀的版本分别计分。所有分页入口在分页前计算相关度，显式指定排序时优先采用指定排序。

索引生成器 v3 修复含假名字段误生成中文拼音的问题。例如 `月が綺麗ねと言われたい！` 原来会把 `綺麗` 转为中文 `qili`，导致搜索七里香的拼音前缀时误命中。现在先做 NFKC，再识别平/片假名（包含规范化后的半角假名）；存在假名时保留原文并使用日语读音 `kirei`，不生成该字段的中文拼音。按字段判断，因此不会因为日语歌手名而禁用其他中文字段的拼音；文件名同样执行这一规则。纯汉字 `綺麗` 仍保留中日候选，因为单凭汉字无法可靠判断语言。

查询侧通过 OpenCC 扩展简繁体；同一词的变体 OR，不同词 AND；读音用 FTS 前缀查询，用户输入经过转义。每个关键词也支持原始字段的包含匹配，保留原有任意位置原文搜索。百分号、下划线和查询操作符不作为用户可执行的搜索语法；罗马音单词内部的撇号可省略。SQL 参数绑定，所有来源/标签/详情范围条件必须包在搜索条件之外共同生效。分页与总数使用同一条件。

面向 2 万首的查询优化将原文规范化提前到数据库迁移/写入；至少三个字符先查 trigram 索引再核验包含，一、二字符使用 SQLite 原生包含匹配。读音 FTS 命中与原文候选先按关键词聚合分数、求交集，再将 ID/分数写入连接内的 TEMP 表供查询和计数复用，避免对整库反复运行 JavaScript 规范化和相关度判断。缓存按数据库写入和跨连接 `data_version` 失效，事务内禁止复用以正确处理回滚；保留已有匹配权重与全部命中结果。

## 后台与前端

歌曲列表选择歌名、歌手、专辑或显示文件名排序时，中文按无声调拼音与英文统一进行 A–Z 自然排序，倒序反转；不再依赖系统语言将中文与英文分组。转换结果在列表组件内有界缓存，刷新查询可复用。日语名称使用后台已有的完整罗马音，与中文拼音和英文混排；同键仍按 ID 稳定排序。默认浏览排序与搜索相关度排序保持原规则。

- 启动后分批补全旧曲库，初始每批 100 首。队列可重启续跑，版本升级可重建。
- 独立 Worker、串行小批处理；遵循纯播放模式的后台工作策略。
- 日语初始化失败时先写基础词条，保留重试任务；重试退避，避免循环占用资源。
- 数据库触发器保证任何写入入口都会入队；后台轮询发现任务。
- 前端关键词传入后端；200ms 防抖、输入法组合态处理、响应序号检查。索引更新后保留搜索词/筛选/排序刷新。
- electron-vite 构建 Worker，electron-builder 携带并解包 Kuromoji 字典。

## 日语名称排序补充

数据库 v8 新增 `song_sort_reading`，从已有搜索词条提取完整日语罗马音并持久化，跳过中文全拼候选；迁移直接回填已有索引，无需重新加载词典或全库重新转换。搜索词条新增、更新、删除时触发器同步清理和更新排序读音。列表批量读取这些短字段，页面仅作键比较，不加载日语词典。

歌名、歌手、专辑、文件名统一适用；例如 `爱你 / Banana / 君が好き / 七里香 / 東京 / Zebra` 按 A、B、K、Q、T、Z 混排。存在假名（含半角假名）时将该歌曲视为日语上下文，纯汉字字段也可采用已有日语读音；整个元数据没有假名时，汉字语言无法可靠判定，继续使用中文拼音。尚未生成读音或转换失败时暂按原文，后台索引更新事件到达后自动刷新排序。

新增实际词典读取、旧索引迁移回填、罗马音提取及中英日混排正逆序回归。原性能报告是在增加排序读音返回字段之前测得，不代表这一扩展后的精确端到端时延。
